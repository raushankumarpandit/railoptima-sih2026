# Indian Railways Automatic Block Planning - Synthetic Dataset Generator

This component generates realistic, reproducible, and internally consistent synthetic historical data for the **Delhi–Ghaziabad corridor** (MVP) to support the Indian Railways Automatic Block Planning application.

> [!NOTE]
> All generated data is purely synthetic and illustrative. It is NOT official or confidential Indian Railways data.

---

## Directory Structure

```text
dataset/
├── source_data/
│   ├── tms/        # Track Management System (track assets, inspections, defects, maintenance)
│   ├── smms/       # Signal Maintenance Management System (signal/S&T assets, inspections, faults, maintenance)
│   ├── tdms/       # Traction Distribution Management System (OHE assets, inspections, faults, maintenance)
│   ├── coa/        # Control Office Application (trains, schedules, blocks, block availability)
│   └── forecast/   # Goods train forecast source
├── master_data/    # Shared reference data (corridors, sections, stations, departments, asset types)
├── canonical_reference/ # The 15 canonical tables generated after source mapping
├── scripts/        # Auxiliary scripts (if any)
└── documentation/  # Supplementary documentation files
```

## Getting Started

### 1. Install Dependencies
Make sure you have Python 3.8+ installed. Install the required python packages using:
```bash
pip install -r requirements.txt
```

### 2. Generate Source and Master Data
Run the following script to generate the synthetic raw data files:
```bash
python generate_all.py
```
This generates the raw databases for TMS, SMMS, TDMS, COA, and Forecast under `dataset/source_data/` and reference tables under `dataset/master_data/`.

### 3. Run ETL to Canonical 15 Tables
Map the source databases to the unified 15 canonical tables:
```bash
python etl_to_canonical.py
```
This maps the generated source tables into the final canonical schema and writes the files under `dataset/canonical_reference/`.

### 4. Run Validations
Validate the integrity, chronology, and constraints of both the source and canonical datasets:
```bash
python validate_all.py
```
This will run comprehensive checks and write the validation results to `validation_report.md`.

## Data Model Files

- **`data_dictionary.csv`**: Contains field names, types, descriptions, and nullable constraints for both source and canonical layers.
- **`source_to_canonical_mapping.csv`**: Outlines mapping rules from raw source tables to the canonical 15 tables.
- **`generation_rules.md`**: Explains the causal relationships, failure rates, temporal guidelines, and logic used during generation.
- **`validation_report.md`**: Generated by the validation script, describing the test results.
